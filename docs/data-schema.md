# You Read, I Read — Data Schema Reference

**Design spec:** `docs/superpowers/specs/2026-04-26-you-read-i-read-design.md` (gitignored; on disk only).

Ground-truth reference for every file in the private data repo. Derived from `scripts/manage_data.py` and `scripts/_common.py`; if this doc contradicts those scripts, the scripts win.

## Conventions

- **Timestamps:** ISO-8601 UTC with a `Z` suffix (`2026-04-26T10:32:00Z`). Generated by `_common.now_iso()`.
- **File formats:**
  - YAML — human-edited files: `tracking/groups.yaml`, `tracking/topics.yaml`, `tracking/apify-spend.yaml`, `preferences/taxonomy.yaml`, `preferences/preference-state.yaml`.
  - JSON — machine-only files: `papers/index.json`, `tracking/state.json`.
  - JSONL — one JSON object per line, `sort_keys=True`, no trailing comma: `preferences/signals.jsonl`.
- **Paper IDs** are stable slugs computed once from the source URL and never changed:
  - `arxiv-<NNNN.NNNNN>` — e.g. `arxiv-2401.12345`
  - `s2-<16-char hex prefix>` — Semantic Scholar 40-char SHA, truncated
  - `doi-<sanitized-doi>` — non-alphanumeric chars replaced by `-`
  - `url-<12-char sha1 prefix>` — everything else, hashed from the raw URL

## Single-writer rule

Every write goes through `scripts/manage_data.py`. The agent never edits data files directly. Exception: `preferences/preference-prompt.md` is hand-edited by the user. Atomic writes use a `.tmp` sibling + rename.

## First-run scaffold

When `papers/index.json` is absent, the first-run flow (in the `paper-data` skill) creates:

| File | Seed content |
|------|-------------|
| `papers/index.json` | `{}` |
| `tracking/groups.yaml` | `{groups: []}` |
| `tracking/topics.yaml` | `{topics: []}` |
| `tracking/state.json` | `{groups: {}, topics: {}}` |
| `preferences/taxonomy.yaml` | `{labels: []}` |
| `preferences/signals.jsonl` | empty file |
| `preferences/preference-state.yaml` | zeroed totals, `recommended_mode: interactive` |
| `.gitignore` | copied from the plugin's `defaults/data-repo-gitignore` |

The data repo's `.gitignore` excludes `tracking/sessions/` (auth state — Apify queryId fingerprints, optional logged-in cookies) plus standard Python / OS / editor noise. **`tracking/sessions/` must never enter git** even though the data repo is private; auth caches are sensitive end-to-end.

## Top-level directory layout

```
~/.you-read-i-read/
├── config.yaml                          # user config (outside data repo)
└── data/                                # private git repo
    ├── papers/
    │   ├── index.json                   # master index, one entry per paper
    │   ├── summaries/
    │   │   └── <id>.md                  # canonical 7-section summary
    │   └── raw/
    │       └── <id>.{html,txt,pdf}      # fetched raw content (optional)
    ├── tracking/
    │   ├── groups.yaml                  # tracked research groups/authors
    │   ├── topics.yaml                  # tracked topics/queries
    │   ├── state.json                   # per-source last-checked watermarks
    │   ├── sessions/
    │   │   └── <source>.json            # opaque per-source session data
    │   └── apify-spend.yaml             # running monthly Apify cost tracker
    └── preferences/
        ├── taxonomy.yaml                # agent's working tag list
        ├── signals.jsonl                # append-only preference event log
        ├── preference-state.yaml        # digested signal totals (derived cache)
        └── preference-prompt.md         # optional free-form user bias note
```

## `papers/index.json`

A single JSON object mapping paper ID → entry. Written by
`manage_data.py paper-add` and `manage_data.py paper-update`.

### Field schema

| Field | Type | Notes |
|-------|------|-------|
| `id` | string | Stable slug. See ID forms in Conventions. |
| `title` | string | Full paper title. |
| `authors` | list of strings | In citation order. Empty list if unknown. |
| `venue` | string | Conference, journal, or preprint server. Empty string if unknown. |
| `year` | integer or null | Publication year. |
| `source_url` | string | Canonical URL used to derive the ID; never changes. |
| `added_date` | string | ISO-8601 UTC; set once on first add. |
| `added_via` | string | `"url"` (manual `/add`), `"update"` (sweep), or other source slug. |
| `labels` | list of strings | User-set tags. Sorted + deduplicated on every write. |
| `auto_tags` | list of strings | Agent-set tags from `preferences/taxonomy.yaml`. |
| `status` | string | `to-read` \| `reading` \| `read` \| `archived`. Default: `to-read`. |
| `one_liner` | string | ≤180 chars. Abstract-derived quick summary for triage cards and `/todo`. |
| `summary_path` | string | Always `papers/summaries/<id>.md` (relative to data repo root). |
| `preference_score` | float or null | Last blended relevance score. Null until first ranking pass. |
| `read_log` | list of objects | One entry per reading session with `started_at`, `finished_at`, `notes`. |

`read_log` entries have `started_at` (ISO-8601 UTC), `finished_at` (ISO-8601 UTC or null), and `notes` (free-form string, may be empty).

### Full example entry

```json
{
  "added_date": "2026-04-20T14:05:12Z",
  "added_via": "url",
  "auto_tags": ["tool-use", "retrieval"],
  "authors": ["Alice Adler", "Bob Bassett", "Carol Chen"],
  "id": "arxiv-2401.12345",
  "labels": ["read-carefully"],
  "one_liner": "Adds a retrieval-then-act loop to a 7B base model, gaining +14% on ToolBench.",
  "preference_score": 0.82,
  "read_log": [
    {
      "finished_at": "2026-04-22T09:44:00Z",
      "notes": "Section 4 has useful ablations on retrieval granularity.",
      "started_at": "2026-04-22T09:10:00Z"
    }
  ],
  "source_url": "https://arxiv.org/abs/2401.12345",
  "status": "read",
  "summary_path": "papers/summaries/arxiv-2401.12345.md",
  "title": "Retrieval-Augmented Tool Use in Language Agents",
  "venue": "arXiv",
  "year": 2024
}
```

`write_json` serializes with `sort_keys=True`, so fields appear alphabetically on disk.

## `papers/summaries/<id>.md`

One Markdown file per paper. Written by `manage_data.py paper-set-summary`
(which reads the body from stdin). Generated by the `paper-summarizer` agent
or inline during `/add`.

### Structure

The file has a YAML frontmatter block followed by seven fixed sections.
The frontmatter mirrors the index entry's metadata so the summary file is
self-contained.

Word budgets come from `summary.max_words_per_section` in
`~/.you-read-i-read/config.yaml` (defaults shown in comments below).

```markdown
---
id: arxiv-2401.12345
title: "Retrieval-Augmented Tool Use in Language Agents"
authors:
  - Alice Adler
  - Bob Bassett
  - Carol Chen
venue: arXiv
year: 2024
source_url: https://arxiv.org/abs/2401.12345
added_date: 2026-04-20T14:05:12Z
status: read
labels:
  - read-carefully
auto_tags:
  - tool-use
  - retrieval
---

## Motivation
<!-- budget: 120 words -->
Language agents exhaust their context window when tool sequences grow long,
leading to repetitive or incoherent plans.

## Problem statement
<!-- budget: 120 words -->
Given a task description and a tool catalog, produce a plan that handles
multi-step dependencies correctly even when prior calls no longer fit in context.

## Challenge
<!-- budget: 120 words -->
Naive RAG retrieves by semantic similarity, but what matters in stateful tool
use is *causal* relevance: which past call produced the value this step needs.

## Insight
<!-- budget: 80 words -->
Treat the execution history as a typed key-value store; retrieve by variable
dependency rather than text similarity.

## Tech details
<!-- budget: 250 words -->
Fine-tuned a 7B Llama-3 base to predict dependency edges; BFS over the graph
retrieves the minimal set of prior calls (median 2.1 vs. 11.4 for baseline).
No external vector store; latency overhead < 40 ms/step on A100.

## Evaluation
<!-- budget: 150 words -->
ToolBench: +14% pass@1 over ReAct. APIBench-Long (≥10-tool tasks): +22%
pass@1, −37% tool calls. Human eval 4.2/5 vs. 3.6/5 for ReAct.

## Important takeaways
<!-- budget: 120 words -->
1. Dependency-based retrieval beats semantic retrieval for stateful tool use.
2. The dependency graph can be built without external supervision.
3. Gains grow with task length.
```

Sections must appear in this order. If the source material (abstract only,
because PDF was unavailable) does not support a section fully, include the
section header with a brief hedge: `(Abstract only — full details unavailable.)`

## `papers/raw/<id>.{html,txt,pdf}`

Fetched raw content stored alongside the summary. Controlled by `summary.store_raw_content` (default: `true`). Extensions: `.html` (WebFetch body), `.txt` (pdftotext extraction), `.pdf` (binary). Used during `/read` sessions to ground follow-up questions with section/page citations. When absent or disabled, follow-ups fall back to the summary text.

## `tracking/groups.yaml`

Tracked research groups or individual authors. Written by
`manage_data.py group-add`.

### Schema

Each group object: `id` (stable slug, auto-derived from `display_name` if omitted), `display_name` (string), `sources` (list of dicts, each with a `kind` key), `added_date` (ISO-8601 UTC).

Source `kind` values:

| `kind` | Extra fields | Notes |
|--------|-------------|-------|
| `semantic-scholar-author` | `id` — S2 author ID (integer as string) | Used by the S2 adapter to fetch recent papers by this author. |
| `arxiv-author-query` | `query` — arXiv author query string | E.g. `"au:Manning_C"`. Used against the arXiv Atom API. |
| `html` | `url` — URL of a group's publications page | Agent fetches and parses the page for paper links. |

### Full example

```yaml
groups:
  - id: stanford-nlp
    display_name: Stanford NLP Group
    sources:
      - kind: semantic-scholar-author
        id: "1741101"
      - kind: arxiv-author-query
        query: "au:Manning_C"
      - kind: html
        url: https://nlp.stanford.edu/publications/
    added_date: 2026-04-20T08:00:00Z
```

## `tracking/topics.yaml`

Tracked research topics with per-source query strings. Written by
`manage_data.py topic-add`.

### Schema

Each topic object: `id` (stable slug), `display_name` (string), `queries` (dict mapping source name → query string; sources: `arxiv`, `semantic_scholar`, `hackernews`, `twitter`, `linkedin`), `added_date` (ISO-8601 UTC).

### Full example

```yaml
topics:
  - id: llm-agents
    display_name: LLM Agents
    queries:
      arxiv: "ti:LLM AND ti:agent OR abs:tool-use"
      semantic_scholar: "LLM agents tool use"
      hackernews: "LLM agents"
      twitter: "LLM agents paper site:arxiv.org"
      linkedin: "LLM agent research"
    added_date: 2026-04-20T08:15:00Z
```

Sources absent from `queries` are skipped for that topic. Twitter and LinkedIn entries are only written when those sources are enabled in `config.yaml`.

## `tracking/state.json`

Per-source last-checked watermarks. Written by `manage_data.py state-set-last-checked`. Two top-level keys, `groups` and `topics`, each mapping entity ID → `{last_checked}` (ISO-8601 UTC). Read before each sweep to determine the `since` cutoff.

### Example

```json
{
  "groups": {
    "stanford-nlp": {"last_checked": "2026-04-25T22:00:00Z"}
  },
  "topics": {
    "llm-agents": {"last_checked": "2026-04-25T22:00:00Z"}
  }
}
```

Watermarks are advanced only after the user fully triages that source's candidates. A source that errors during a sweep does not have its watermark advanced.

## `tracking/sessions/<source>.json`

Opaque per-source session data: cached cookies, platform query IDs, rate-limit tokens, etc. Written by source adapters; structure is internal to each adapter and may change without notice. The file is absent if that source has never run a successful session.

**Twitter example:**

```json
{"bearer_token_cached": "AAAA...redacted", "last_refreshed": "2026-04-25T20:00:00Z", "query_id": "oMVVkncK"}
```

**LinkedIn example:**

```json
{"cookies": {"JSESSIONID": "ajax:12345678901234567", "li_at": "AQED..."}, "last_refreshed": "2026-04-25T19:45:00Z"}
```

These files may contain secrets (session cookies, tokens). The data repo must remain private.

## `tracking/apify-spend.yaml`

Running month-to-date Apify cost tracker. Updated before and after each Apify
MCP call by the agent. Read by `/sync status` to report current spend.

Fields: `month` (`YYYY-MM`; reset on rollover), `spend_usd` (dict mapping source → cumulative USD float), `last_updated` (ISO-8601 UTC).

### Example

```yaml
month: 2026-04
spend_usd:
  twitter: 0.42
  linkedin: 4.10
last_updated: 2026-04-26T10:32:00Z
```

Before each call, the agent checks `spend_usd[source]` against `tracking_sources.<source>.max_apify_usd_per_month` (default `$10`). When the cap is approached, the call is skipped, the deferral logged, and the user notified.

## `preferences/taxonomy.yaml`

The agent's working tag list. When tagging a new paper the agent picks from this list or adds an entry if none fit. Top-level key `labels` is a list of `{name, description}` objects: `name` is a short lower-case hyphenated tag; `description` is one sentence.

### Example

```yaml
labels:
  - name: tool-use
    description: Papers where LLMs call external tools, APIs, or code interpreters.
  - name: retrieval
    description: Papers using retrieval-augmented generation or external memory.
  - name: benchmark
    description: Papers whose primary contribution is a new evaluation benchmark.
```

## `preferences/signals.jsonl`

Append-only ground-truth event log. One JSON object per line; `sort_keys=True` serialization. Written by `manage_data.py signal-log`. During `/update` ranking the agent reads the most recent ~100 lines directly into the ranking prompt — no pre-aggregation needed.

Every record has `ts` (ISO-8601 UTC), `event` (string), and `paper_id` (present on most events). Additional fields vary by event type.

### Event vocabulary

| Event | Meaning | Additional fields |
|-------|---------|-------------------|
| `update_accepted` | User pressed `[a]` during `/update` triage. | `paper_id`, optionally `tag` (topic or group that surfaced this paper). |
| `update_rejected` | User pressed `[s]` during `/update` triage. | `paper_id`, optionally `reason` (free-form, if the user typed one). |
| `read_started` | A `/read` session opened for this paper. | `paper_id`. |
| `read_finished` | User confirmed "Done" at session end, or ran `/done <id>`. | `paper_id`, optionally `notes`. |
| `archived_without_reading` | User ran `/archive <id>`. | `paper_id`, optionally `reason`. |
| `add_via_url` | Paper was added via `/add <url>` directly (not from a sweep). | `paper_id`. |
| `labeled_manually` | User added or removed a label outside of a sweep. | `paper_id`, `label`, `action` (`added` or `removed`). |

### Example lines

```
{"event": "update_accepted", "paper_id": "arxiv-2401.12345", "tag": "llm-agents", "ts": "2026-04-20T14:05:12Z"}
{"event": "update_rejected", "paper_id": "arxiv-2401.99999", "reason": "pure benchmark, no method", "ts": "2026-04-20T14:06:01Z"}
{"event": "read_finished", "notes": "very useful ablations in sec 4", "paper_id": "arxiv-2401.12345", "ts": "2026-04-22T09:44:00Z"}
{"event": "archived_without_reading", "paper_id": "arxiv-2312.00042", "reason": "too applied for current interests", "ts": "2026-04-25T11:22:30Z"}
```

Fields appear alphabetically on disk (enforced by `sort_keys=True`).

## `preferences/preference-state.yaml`

A small derived cache updated atomically on every signal-log call. Its sole purpose is to provide deterministic signal counts for threshold decisions (e.g. when to recommend `semi-auto` mode). It is **not** the substrate of preference scoring — the agent reads `signals.jsonl` directly for that.

**This file does not contain `tags`, `recent_positives`, or `recent_negatives`.** Those were dropped in the LLM-prompt-driven preference design: the agent reads the tail of `signals.jsonl` into the ranking prompt directly, so no tag-buckets or recent-rings are needed.

Fields: `totals` (dict with `signals`, `accepted`, `rejected`, `read_finished`, `archived_without_reading` counts), `recommended_mode` (`interactive` < 25 signals / `semi-auto` 25–99 / `full-auto` ≥ 100), `last_recomputed` (ISO-8601 UTC).

### Example

```yaml
totals:
  signals: 47
  accepted: 18
  rejected: 25
  read_finished: 12
  archived_without_reading: 4
recommended_mode: interactive
last_recomputed: 2026-04-26T10:32:00Z
```

Thresholds are hardcoded in `manage_data.py:_recommend_mode`. The agent surfaces a suggestion when `recommended_mode` differs from the current `config.yaml` mode but never auto-flips it.

## `preferences/preference-prompt.md`

**Optional.** Free-form text hand-edited by the user. Loaded verbatim into the `/update` ranking prompt when present; absent or empty means no bias. This is the only file in the data repo not managed by `manage_data.py`.

### Example content

```
prefer methods over benchmarks
soft-prefer tool-use and retrieval papers
hard-reject anything purely applied with no theoretical contribution
I'm currently deep in agentic systems; boost papers on multi-agent coordination
skip survey papers unless they cover an area I haven't tracked before
```

The agent injects it verbatim under a "User preferences" heading. Keep it under ~200 words for best results.
